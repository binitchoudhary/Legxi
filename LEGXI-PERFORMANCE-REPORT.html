Fixes Implemented — Code Before & After
Fix 1 — Google Fonts: Render-Blocking → Non-Blocking layout/theme.liquid LCP −300ms
BEFORE — Render Blocking
<link href="https://fonts.googleapis.com/
css2?family=Rajdhani:wght@600;700&
family=Wallpoet&display=swap"
rel="stylesheet">

⚠ Browser STOPS rendering page
  until this font CSS is downloaded,
  parsed, and font files requested.
  Blocks First Contentful Paint.
AFTER — Non-Blocking Async
<link rel="preload"
  href="https://fonts.googleapis.com/
  css2?family=Rajdhani:wght@600;700&
  family=Wallpoet&display=swap"
  as="style"
  onload="this.onload=null;
          this.rel='stylesheet'">
<noscript>
  <link href="..." rel="stylesheet">
</noscript>

✓ Font CSS downloads in parallel.
  Page renders immediately.
  Fonts swap in when ready (display=swap).
  noscript fallback for JS-off browsers.
Expected improvement: Eliminates 1 render-blocking resource. LCP improves by ~250–350ms on slow connections. FCP improves by same margin. Google PageSpeed "Eliminate render-blocking resources" warning removed.

⚠ 7 third-party domains had no

BEFORE — No Module Preload

  src="{{ 'vendor.min.js' | asset_url }}">
</script>
<script type="module"

</script>

⚠ ES modules are deferred but

  (after importmap is parsed).
  Module graph resolution and

AFTER — Preloaded Module Graph

  href="{{ 'vendor.min.js' | asset_url }}">

  href="{{ 'theme.js' | asset_url }}">

</script>

✓ Browser downloads, parses, and
  compiles JS modules in parallel
  with HTML parsing.
  Interactive sooner = better INP.
Expected improvement: rel="modulepreload" tells the browser to download AND parse/compile the JS modules immediately (not just download). The theme becomes interactive 30–80ms sooner. Eliminates the "module evaluation" delay that can cause first interaction to be slow (INP improvement).
Fix 4 — GoKwik Country Detection: DOMContentLoaded → requestIdleCallback snippets/gokwik.liquid INP + CLS
BEFORE — Blocks Main Thread
document.addEventListener(
  "DOMContentLoaded",
  getCountryData
);

⚠ Fires fetch() + style injection
  immediately when DOM is ready.
  Competes with critical rendering
  tasks for main thread time.
  The style injection (display:none
  on checkout buttons) can cause
  visible CLS / button flash.
AFTER — Idle Time Scheduling
document.addEventListener(
  "DOMContentLoaded",
  function() {
    if ('requestIdleCallback' in window) {
      requestIdleCallback(
        getCountryData,
        { timeout: 2000 }
      );
    } else {
      setTimeout(getCountryData, 1);
    }
  }
);

✓ Browser schedules fetch when the
  main thread is idle. Timeout:2000
  ensures it still runs within 2s
  even if browser stays busy.
  Fallback for Safari (setTimeout).
Expected improvement: Country detection no longer competes with LCP rendering or first interaction for main thread time. INP improves because the main thread is free during initial user interactions. CLS risk from style injection is reduced (style is applied during idle, not during critical rendering). Safari gets a setTimeout(fn, 1) fallback since Safari doesn't support requestIdleCallback.

4
Skipped Fixes — Risk Assessment

⚠ Firebase Scripts — Cannot Add defer Safely

Why skipped: The certificate authentication page has two Firebase scripts (firebase-app-compat.js + firebase-auth-compat.js, ~300 KB combined) loaded synchronously. Adding defer would require the main 2000-line auth IIFE to also be deferred — otherwise init() → initFirebase() → firebase.initializeApp() runs before Firebase loads, breaking authentication entirely.

Impact if skipped: Only affects /pages/authentication which is noindex, nofollow. Zero impact on main site performance or Google rankings.

Future fix (requires dev work): Wrap the entire auth IIFE in a window.addEventListener('load', function() { ... }) callback, then add defer to Firebase. Estimated effort: 2–4 hours testing.

⚠ theme.js Code Splitting — Requires Build Pipeline

Why skipped: theme.js is 293 KB. Splitting it into critical/non-critical chunks requires a webpack/rollup build pipeline and Shopify's asset pipeline changes. This is a Shopify-managed file (part of the purchased theme), and modifying it risks breaking future theme updates.

Impact if skipped: theme.js uses type="module" (browser-deferred). It doesn't block rendering. The 293 KB is parsed and executed after DOM is ready. INP impact is manageable.

Mitigation already applied: rel="modulepreload" added to pre-parse and compile theme.js in parallel with HTML parsing.

⚠ GoKwik MutationObserver on document.body — Vendor Code

Why skipped: GoKwik's integration observes the entire document body (childList: true, subtree: true) via MutationObserver. This is vendor code injected by the GoKwik integration. Modifying it risks breaking checkout button state tracking. The observer is debounced at 700ms and disconnects/reconnects, which partially mitigates the impact.

Recommendation: Contact GoKwik to request an optimized integration script that observes only the checkout button container rather than the entire body.
